# Проверка изменений и подготовка Dropo 3.1.5

Дата: 7 ноября 2026. Приложение проверено относительно публичной 3.0.55:
`ab30758` → изменения партнёра `e29eeb0` → исправления этого выпуска.
Бэк проверен относительно `c5587c4` → `e28d47a` → исправления очереди и политики.

## Изменения партнёра

- Индивидуальные Free/Turbo-профили, защищённое хранение и привязка установки.
- Контроллер, агенты серверов, собственный DoH, подарки и административная выдача
  Турбо. Продажи в работающем API выключены.
- Отдельные короткие web-сессии админки с CSRF/Origin; native bearer не даёт
  административный web-доступ.
- Обновления сетевых зависимостей, исходники runtime, защита публикации Actions.
- Однократный штатный Google Play In-App Review и ручная ссылка на магазин.

## Исправления перед выпуском

- Прямые адаптивные маршруты Android ограничены режимом «По сервисам»; полный
  VPN не получает эти исключения. Старые кеши графа инвалидируются.
- Отменённая задача прошлого подключения не меняет расписание нового.
- Загрузка персонального профиля ограничена общим тайм-аутом, включая тело.
- Удаление аккаунта очищает управляемые локальные ключи с повтором при ошибке,
  сохраняя личные подписки. Новый аккаунт использует собственную идентичность;
  поздняя загрузка после выхода не возвращает старые ключи.
- Очередь бэка отдаёт приоритет отзыву/удалению и продолжает другие события после
  ошибки. Повтор после потери подтверждения не меняет срок в том же event ID.
- Политика и памятка Play исправлены под персональные профили, DoH и backups.
- Windows package gate запускается до слияния PR без пропусков по путям.
- Вход по тестовому паролю до добавления Free получает обычный отдельный гостевой
  профиль. Его удаление доступно отдельно, не меняет права общего аккаунта и не
  теряет секрет при удалении другого профиля.
- Сборки восстанавливают только зависимости из lockfile; отсутствие точного
  пакета в кеше больше не приводит к незаметному понижению версии.
- Списки Re-filter обновлены до 07112026.

## Проверено локально

- Flutter analyze без замечаний; 612 тестов прошли; после последнего усиления
  запрета неявной привязки отдельно повторены 12 тестов профилей.
- Android Kotlin: 66 тестов, включая Google Play review и ссылки магазина.
- Windows Go, Android core и bridge с закреплённым XHTTP overlay: тесты и vet.
- Backend: 304 теста/подтеста; vet. Controller/agent/DNS: тесты и vet; PostgreSQL
  integration требует Linux CI. Monitoring: 20; доступные Windows hardening: 5.
- Регрессии доверия publisher и вложенных Actions: 13; readiness: 24;
  PowerShell syntax: 40 scripts.
- Метаданные участников, UTF-8 и account-origin/build contract.

Подписанные APK/AAB проверяются после сборки. Package Play — `com.dropo.myapp`,
versionCode — 30105; AAB остаётся в локальном архиве. Физический телефон не
проверялся. Чужие прежние VM/эмуляторные отчёты не выдаются за тест этой сборки.

## GitHub: применено и оставшиеся шаги

На обоих репозиториях Actions закреплены по полному SHA, default token read-only,
Actions не одобряют PR. Разрешены GitHub-owned actions; в app дополнительно только
закреплённый publisher softprops. Flutter setup сохранён локально с лицензией и
проверкой происхождения; вложенные cache actions тоже закреплены. Внешние PR публичного app требуют
approval. В приватном бэке fork workflows и передача secrets/write tokens выключены.
Dependabot alerts и security updates включены для обоих репозиториев.

В app активны запрет удаления/force-push основной ветки и запрет изменения/удаления
`v*` tags, без постоянного bypass. API подтверждает `protected=true`:
[ветка](https://github.com/sunnydjam/dropo-by-sunnydjam/rules/26748365),
[теги](https://github.com/sunnydjam/dropo-by-sunnydjam/rules/26748366).
Это не означает включения независимых approvals или required checks.

Независимый reviewer и release environment approval ожидают подтверждения
владельца. Действительные имена проверок app: `contributor-guard`, `windows-tests`,
`flutter-tests`, `go-race`, `platform-compile (linux, amd64, dropo-linux-test)`,
`platform-compile (darwin, arm64, dropo-darwin-test)`, `clean-windows-package`.
Backend: `test`, `infrastructure`. Контексты принадлежат GitHub Actions app15368.
Private backend rulesets и classic protection возвращают403 с требованием Pro;
репозиторий не переводился в public. Создание tags доверенным publisher/owner
ещё не ограничено отдельным правилом. 2FA/recovery не проверены.

После включения Dependabot исправлены пять предупреждений в инструментах
оператора: cryptography50.0.0, requests2.33.0. Проверены отдельное окружение,
SSH-ключи, шифрование/расшифровка и отказ при подмене backup. Это не обновление
установленных на серверах Python-пакетов. Частную рабочую копию партнёра нужно
синхронизировать с изменённым requirements перед следующим экспортом.

Backend PR#4 на коммите `98dbe3e` прошёл обе Linux CI-проверки, включая
PostgreSQL integration и backup receiver. Ошибка проверки временного merge-автора
GitHub устранена без изменения правил авторства реальных коммитов.

## Что ещё требуется для публичного запуска

- Доверенный сертификат Windows и настройка подписи: существующий stable gate
  отказывает неподписанному installer. Текущая сборка остаётся pilot/draft.
- Актуальный SSH-доступ к серверу для выкладки исправлений бэка и публичной
  политики. В рабочей области партнёра указана защищённая operator-папка,
  отсутствующая на этом ПК. Исходники и бинарник не означают deployment.
- Проверка новой опубликованной политики перед отправкой AAB и Data safety.
- Учет retention backups: старше30дней, но минимум7копий могут оставаться дольше;
  служебные tombstones пока без auto-expiry. Восстановление старой БД требует
  отдельной сверки последующих удалений и отзывов; автоматической процедуры нет.
- Проверка мощности московского входа: предыдущие документы фиксируют высокое
  давление CPU. В этой проверке нагрузка на production не создавалась.

Legacy-подписки, UUID, серверные данные, ключи и сетевые настройки рабочего ПК
не удалялись и не переключались. Проверка не является гарантией отсутствия всех
ошибок или независимой сертификацией Google.
