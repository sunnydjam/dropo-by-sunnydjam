# План улучшения 1

Статус: сохранён для последующей реализации  
Дата фиксации: 30 августа 2026 года  
Базовая версия: `v3.0.26` (`fb7206f`), ветка `Dzhamuha-develop`

## Прогресс в `v3.0.27`

- CI-проверки Go и Flutter переведены в fail-fast режим.
- Устранено небезопасное преобразование WinINet `uintptr` обратно в указатель;
  layout нативного union закреплён Windows-тестом.
- Release gate и автоматическая публикация Windows-артефактов переведены на
  фактическую релизную ветку `Dzhamuha-develop`.
- Добавлена проверяемая цепочка автоматического обновления установленной
  Windows-версии из GitHub Releases.
- Полный интеграционный тест сохранения и восстановления proxy-состояния из
  пункта 3 остаётся отдельной задачей и не считается закрытым.

## Цель

Подготовить DropoVPN к полноценному публичному Windows-релизу, сохранив уже
работающую direct-first архитектуру: выбранные сервисы используют `VPN` или
`Zapret`, а игры, Steam и весь неизвестный трафик по умолчанию идут напрямую.

Переписывание сетевого ядра не требуется. Работа должна сосредоточиться на
надёжности релизного контура, честном отображении состояния, доступности
интерфейса, поддерживаемости кода и доказуемой проверке Zapret-стратегий.

## Зафиксированное состояние

- Режим «Всё через VPN» использует TUN.
- Режим выбранных сервисов работает по принципу direct-first.
- Единственным владельцем WinDivert на Windows является встроенный
  `app/trafficorchestrator`.
- Неизвестный или недостаточно классифицированный трафик проходит без изменений.
- Правила LAN, рабочих сетей и WireGuard overlay имеют приоритет.
- Для Steam и игр существуют регрессионные проверки прямого трафика.
- Каталог Zapret версии 15 содержит 27 нативных методов YouTube и 26 нативных
  методов Discord, включая адаптированные профили Flowseal 1.10.2.
- Discord Zapret остаётся экспериментальным; рекомендуемый стабильный маршрут
  для приложения и voice — VPN.
- Desktop Go, Android core, launcher и Flutter-тесты проходят; `flutter analyze`
  не находит ошибок.

## Спринт 1 — надёжность релиза

Приоритет: критический. Выполнить до дальнейшего расширения функций.

1. Сделать CI fail-fast: после каждого `go test`, `go vet`, `govulncheck` и
   скрипта сборки явно проверять код завершения.
2. Исправить обнаруженную ошибку `go vet` в
   `app/windows_proxy_connection_windows.go`: исключить небезопасное
   преобразование `uintptr` в `unsafe.Pointer` при чтении WinINet.
3. Добавить Windows-тест чтения и восстановления системной proxy-конфигурации.
4. Исправить отображение Zapret: пользователь должен видеть выбранную политику
   `Zapret`, название активной стратегии и результат проверки, а не внутренний
   outbound `Direct`.
5. Переименовать общее состояние «VPN активен» в точное состояние, например
   «Подключено · выборочная маршрутизация».
6. Устранить противоречие Direct/VPN/Zapret/Auto в `ROUTING_CONTRACT.md`.
7. Обновить раздел поддерживаемых версий в `SECURITY.md`.
8. Определить единственную релизную ветку и согласовать с ней `ci.yml`,
   `windows-release-gate.yml` и `release.yml`.
9. Исправить базовую accessibility-семантику боковой навигации и исключить
   скрытые страницы из дерева доступности.
10. Подготовить процесс Authenticode-подписи перед широким публичным релизом.

### Критерии готовности спринта 1

- CI завершается ошибкой при искусственно вызванном сбое любой проверки.
- `go vet ./...`, все Go-тесты, Flutter analysis и Flutter-тесты проходят.
- На главном экране Zapret никогда не отображается как пользовательский Direct.
- Навигация полностью доступна с клавиатуры и корректно читается screen reader.
- Release gate запускается для фактической релизной ветки.
- Steam, игры и посторонние сайты сохраняют прямой маршрут.

## Спринт 2 — интерфейс и поддерживаемость

1. Разделить `flutter_app/lib/main.dart` на модули:
   `core_bridge`, `models`, `home`, `routing`, `profiles`, `settings`,
   `diagnostics` и `design_system`.
2. Выполнить первый этап рефакторинга без изменения поведения приложения.
3. Разделить пользовательское состояние сервиса на четыре поля:
   выбранная политика, эффективная стратегия, здоровье сервиса и источник
   измеряемой задержки.
4. Показывать на главном экране только закреплённые и активные сервисы, остальные
   открывать по кнопке с поиском.
5. Добавить поиск по каталогу сервисов и выбор недавно запущенного приложения с
   отображением полного пути к executable.
6. Добавить ограниченные пользовательские маршруты Direct/VPN по hostname и
   приложению. Не разрешать произвольный Zapret или IP-only Zapret без
   типизированного нативного правила и тестов.
7. Перенести длинные технические названия стратегий в раскрываемые подробности;
   добавить понятные метки «Рекомендуемая» и «Экспериментальная».
8. Постепенно заменить polling состояния каждые 800 мс на события core и единое
   сессионное состояние.
9. Либо реализовать полноценную Flutter-локализацию через ARB, либо временно
   убрать неработающую настройку языка.
10. Проверить интерфейс при масштабировании Windows 125%, 150%, 175% и 200%.

### Критерии готовности спринта 2

- Основной Flutter-файл больше не содержит весь UI и три реализации bridge.
- Рефакторинг не меняет маршрутизацию и проходит существующий release gate.
- Пользователь однозначно понимает, какой сервис идёт Direct, VPN или Zapret.
- Длинные списки не обрезаются на минимальном поддерживаемом размере окна.
- Пользовательские маршруты не могут создать глобальный перехват IP-трафика.

## Спринт 3 — стратегии и диагностика

1. Ввести раздельную матрицу здоровья: Web, desktop-приложение, TCP gateway,
   UDP/QUIC и voice/media.
2. Сохранять доказанную стратегию только после успеха всех обязательных целей
   сервиса; частичный успех не сохранять.
3. Оставить автоматический поиск Discord экспериментальным до надёжного
   подтверждения продолжительного двустороннего media-трафика.
4. Показывать сеть, время последней проверки, номер стратегии и состояние
   fallback без раскрытия чувствительных сетевых данных.
5. Добавить экспорт обезличенного диагностического пакета. Автоматическую
   телеметрию и автоматическую отправку логов не включать.
6. Создать контролируемую процедуру сравнения новых релизов Flowseal с текущим
   каталогом: лицензия, аргументы, payload-хеши, typed mapping, fixture tests и
   Steam/shared-address regression.
7. Скрыть или удалить из пользовательского каталога методы, не имеющие рабочей
   нативной Windows-реализации.
8. Поднимать тестовое покрытие desktop core до 45%, launcher до 25%, сохраняя
   не менее 65% для `trafficorchestrator`.

### Критерии готовности спринта 3

- YouTube подтверждается минимум по web и media-целям.
- Discord не получает статус «Работает» только по HTTP-проверке.
- Кэш стратегии инвалидируется при смене сети или версии каталога.
- Ни одна стратегия не меняет пакет неизвестного сервиса на общем IP-адресе.
- При неудаче Zapret приложение безопасно использует разрешённый VPN fallback
  либо Direct, не затрагивая игры и Steam.

## Порядок возврата к плану

При возобновлении начать со спринта 1 и не добавлять новые стратегии или
широкие правила перехвата, пока CI не станет fail-fast и пользовательское
состояние Zapret не будет отображаться корректно.
